# Commander 模式的镜像传输工作台

状态：2026-10-27，交互讨论稿，尚未实施。
英文主文档见 [transfer-workspace.md](transfer-workspace.md)。
本文把[项目模型](project-model.zh-CN.md)和[用户流程](user-journeys.zh-CN.md)
落实为可以浏览、复制和检查结果的工作台。

## 核心操作：打开两个地方，把选中的镜像复制过去

左右面板顶部**各有一个目标下拉框，直接选择具体位置**。
同一个下拉列表里放公司镜像仓库、本机 Docker 镜像库、下载目录等目标，
不用先选择类型、再使用第二个下拉框选择位置。两边共享目标列表，各自独立选择。
根据 2026-10-28 的工作区反馈，每边只保留紧凑的可折叠 Tree，移除表格/列表切换。
名称使用整行可用宽度，平台、摘要和大小通过“检查”查看，避免空列占据空间。
两边都能浏览内容，下方能看到传输任务。用户操作的是具体镜像，
可以直接看到来源和目标，不需要先学习命令、打 Tag 或填写完整镜像地址。

```text
ImagePort        管理目标        传输任务            语言  外观
──────────────────────────────────────────────────────────────────
[本机 Docker 镜像 ▾]              │ [公司镜像仓库 ▾]
引擎：当前上下文                   │ 账号：发布账号 [更换]
搜索 / 刷新                       │ 搜索 / 刷新
──────────────────────────────────│───────────────────────────────
▾ service-api                     │ ▾ Edge 项目
    1.4   arm64                   │   ▾ service-api
▸ worker                          │       1.3
                                  │   ▸ worker
                                  │ ▸ 生产项目
[复制到 Edge 项目 →]              │ [← 复制到本机镜像]
──────────────────────────────────────────────────────────────────
传输队列：本机 → 公司仓库 / Edge  service-api:1.4  正在核验
```

示意中的名称和数据仅作讨论，不是程序预置数据。这是操作结构，不是最终视觉稿。

## 每个下拉框直接列出可去的目标

主界面以左右面板和底部队列为中心，顶部提供“管理目标”和传输历史入口，
不依赖额外侧边栏切换本机或远端。这替代上一版“类型 + 具体仓库”的两级选择草图。
项目、镜像、镜像文件的对象定义保持一致。

下拉内容示意如下，类型只作分组标题，实际点击的是具体目标：

```text
本机镜像
  本机 Docker 镜像          当前已有引擎
镜像仓库
  公司镜像仓库              registry.example.com
  测试镜像仓库              test-registry.example.com
文件系统
  下载目录                  /Users/example/Downloads
  镜像导出目录              /Users/example/Images
───────────────────────────────────────────────
添加目标……
管理目标……
```

两边下拉框使用同一份目标配置，任意一边都可选择任意目标，也可以同时打开同一个目标。
同名目标用类型和地址或路径区分；离线目标显示状态，不从列表悄悄消失。

| 目标类型 | 直接选择的具体位置 | 下方怎么展开 |
| --- | --- | --- |
| 镜像仓库 | 某个已保存的仓库服务 | 项目 → 镜像名称 → 版本 |
| 本机镜像 | 某个已有 Docker 引擎或上下文 | 镜像名称 → 版本，详情显示平台和内容标识 |
| 文件系统 | 某个本地磁盘根位置或目录 | 文件夹 → 镜像文件 → 检查后的镜像条目 |

这里把用户说的“pull 到本地磁盘”对应为**本机镜像库**，界面标为“本机镜像（Docker）”。
它接收 pull/load 的结果；文件系统接收导出的 tar 等文件，二者分别浏览和核验。
不要求用户找到或操作 Docker 引擎内部的存储目录。

选择一个具体仓库后读取项目树，需要时登录；增加连接不等于在服务器上创建项目。
账号和连接状态单独显示，更换账号后重新读取，不把权限混在一起。

在树里选中或打开一个项目，才确定上传目标。只选到仓库根节点时，复制前需要选项目，
不能自动采用第一个项目。收藏项目可以直接定位到对应仓库和项目节点，减少重复选择。
因此仍然是“把镜像放进哪个项目”，同时允许用户先打开仓库浏览。

每边独立保留位置、展开状态、搜索和选择。切换目标时，清除不适用的旧选择，
明确显示新位置；恢复旧位置时也需检查访问状态。已排队任务不跟着改变。
两边可以同为仓库、同为本机或文件系统，不固定一边只能是本地。

每边只保留 Tree，保留清晰的正文字号，通过收紧控件间距和移除空列扩大展示空间。
折叠箭头只改变展开状态，不等于勾选或发起复制；键盘也能导航和展开。
子项按需读取并保留后端分页，区分加载中、空、无权限、不支持列举和读取失败。
不能列举时仍可填写已知项目或镜像地址。

不提供全仓库镜像平铺表格，也不递归预取所有仓库和标签；远端不一定支持全量列举。
保留路径输入和“上一级”。打开镜像只浏览版本或详情，不立即传输，也不通过展开操作缩小平台范围。
本机无标签镜像和多名称镜像要显示真实身份，不虚构版本名称。

因此，“本机在左、远端在右”只是常用起点，不限制项目之间的复制。
项目在界面只出现一份，多个账号仍然是这个项目的不同访问方式。
重新打开应用时，可以恢复上次位置；连接失败或登录失效必须如实显示。

## 单独管理下拉框里的目标

顶部“管理目标”和两个下拉框底部的同名入口，打开同一个配置管理页面或窗口。
列表展示名称、类型、地址或路径、连接状态，提供添加、编辑和移除。
只有在“添加目标”配置时，才需要选择它是什么类型：

- **镜像仓库配置**：名称、地址、服务类型、连接与证书设置；单独关联账号凭证，
  一个仓库可以有多个账号，但在目标列表里仍是一份仓库配置。
  测试连接采用不写入内容的检查，只报告已经核验的结果。
- **本机镜像配置**：选择已有引擎或上下文、设置名称、检查能否访问；
  可以发现当前上下文，不替用户启动引擎或修改系统权限。
- **文件系统配置**：选择磁盘根位置或目录、设置名称、显示实际路径和可访问状态。

保存后，两边下拉列表同步更新。如果从某个面板发起新增，可以直接在该边打开新目标，
另一边保留原状态。仓库里的项目和镜像是之后读取的内容，不要求在目标配置里逐个录入。

“移除目标”只移除本地配置，不删除仓库镜像、本机镜像或文件。
删除凭证另行明确处理。编辑或移除配置不能把已排队任务改投到其他位置；
任务保留原来确认的目标与身份，缺少访问条件时说明原因，更换目标需重新确认。

## 上传：选中镜像，复制到已经打开的项目

以 service-api:1.4 为例：

1. 左边下拉框直接选“本机 Docker 镜像”；右边直接选“公司镜像仓库”，展开 Edge 项目。
2. 选中 service-api:1.4，点击“复制到 Edge 项目”。
3. 一个简短确认里展示来源、目标、访问账号、目标名称、版本和平台范围，
   默认带入原名称与版本，允许修改。若选中了目标镜像组，应明确显示名称映射。
4. 必要时在这里选择账号或登录，保留所有输入；有版本冲突时处理冲突。
5. 确认一次后加入下方队列，可以继续浏览其他镜像。
6. 核验成功后，若右边仍显示该项目，刷新后能看到新版本；任务提供“打开目标”。
   如果用户已经切到其他项目，不强行把面板切回去。

不用要求用户先执行独立的 Tag 操作。拖拽可以在后续作为同一确认流程的快捷入口，
初版应先让可见的复制按钮走通，不能只支持拖拽，也不双击立即上传。

反向复制也是同一逻辑：从项目选镜像，复制到本机。项目之间复制也是一样，
来源和目标分别使用相应账号；同一仓库的两个项目也可能使用不同账号。
底层不支持某条路线时，在排队前说清楚，不能偷偷替换身份。

### 两个目标决定具体怎么传输

| 来源 → 目标 | 实际动作与结果 |
| --- | --- |
| 镜像仓库 → 镜像仓库 | 把镜像复制到目标项目 |
| 镜像仓库 → 本机镜像 | Pull 到选中的引擎，在本机镜像列表可见 |
| 本机镜像 → 镜像仓库 | 上传到选中的项目，本机原件保留 |
| 镜像仓库或本机镜像 → 文件系统 | 导出镜像文件到选中的目录 |
| 文件系统里的镜像文件 → 本机镜像 | 检查并选择内容后 Load 到选中的引擎 |
| 文件系统里的镜像文件 → 镜像仓库 | 检查并选择内容后上传到选中的项目 |

用户都从“复制”发起，确认时再用上传、拉取、导出或导入说明具体结果。
具体路线由实际目标类型和选中内容决定，不取决于哪边是左边。
无效组合要在排队前说明缺少什么；两个文件系统目标不意味着本工具要承担普通文件管理。

## 镜像文件如何放进来

在下拉框选择具体目录或磁盘目标，浏览电脑上的真实目录和文件，始终显示实际路径。
镜像文件经过检查后可以展开其中的镜像条目和平台范围，再复制到另一边的项目或本机。
多镜像文件在导入前选择具体条目和范围。普通文件仍按普通文件展示，不能发起镜像导入；
不支持或损坏的归档说明检查结果，不能伪装成空镜像列表。

另一边打开文件夹时，“复制”明确表示“导出镜像文件”，默认使用该目录，
再确认文件名、格式和内容范围，
进入同一传输队列。目标文件已存在时，需要明确的覆盖选择。

已有归档文件不作为可以任意追加内容的普通目录。打开它是检查内容；
导出是创建文件，不默认改写正在浏览的归档。
“复制到本机镜像”和“导出到电脑上的文件”要分开表达，结果也分别核验。
文件来源项目只是说明，可以导入其他项目，不携带账号密码。

## 队列负责说明传输到了哪一步

每条任务显示镜像、来源、目标、所用账号、状态和可用操作。
下方展示当前任务，“传输任务”页面查看完整历史和错误详情。

- 状态包括等待、复制、核验、完成、需要登录、失败、取消中、已取消、待核实。
- 有实际测量时才展示大小、速度、百分比和预计时间；没有总量就展示当前阶段。
- 活动任务可以请求取消；符合条件的失败可以重试；核验成功后可以打开目标。
- 中断结果不明时先检查目标；取消后说明已完成的部分，不承诺自动撤销。
- 未确认底层支持前，不提供承诺断点续传的“暂停 / 继续”。

排队时固定来源内容、目标路径、平台范围和两边账号。之后切换面板、默认账号，
都不会改变已排队任务。登录续期回到原任务；拒绝访问不会自动换高权限账号。
批量任务逐项报告结果，避免重试时把已完成的也重新复制。

## 清理就在当前位置做

选中镜像版本，选择“从 Edge 项目删除……”或“从本机删除……”，
展示实际受影响的名字和内容，单独确认删除权限，再执行与核验。
删除按钮与复制按钮分开，避免误操作。

版本名不是普通文件夹。创建另一个名称走复制流程；移除旧名称，若底层支持，
也需要独立的删除确认。不能把“改名”或拖拽悄悄变成删除原件。
初版不提供自动移动、目录同步或自动删除目标多余镜像。

移除项目快捷入口、移除账号、删除归档文件，都要明确各自范围；
不能把它们混成同一个“删除”。其他位置的副本不会连带删除。

## 后续按这些步骤验收

1. 首次使用：读取真实本机镜像，在另一边添加项目、登录、复制，并找到远端结果。
   分别验证单个下拉框直接选择仓库、引擎和目录，以及项目树展开；切换目标不改变排队任务。
   Tree 的加载、分页、空和错误状态可区分，不依赖远端提供全量镜像列表。
2. 反向复制：项目镜像进入本机引擎列表，不能只生成 tar 文件。
3. 项目互拷：两边分别使用所选账号；不支持的路线在排队前说明。
4. 文件往返：导出、检查条目，再导入不同项目，原项目和文件都仍然保留。
5. 中途处理：复制时能浏览其他位置，登录过期或版本冲突不丢输入，任务目标不漂移。
6. 清理：只删除确认位置的指定范围，其他项目、本机副本和文件各自独立。
7. 目标配置：创建和编辑仓库、引擎、目录配置，两边下拉框同步更新；
   同一仓库的多个凭证不制造重复项目，移除配置不删除内容或改投排队任务。

这些是后续实现的验收场景，本轮没有执行真实上传或删除。
现有 From/To 页面可以作为实现起点，但仍需按上述流程改造和验证。

数据和传输是模拟的，验证范围见[原型说明](prototype/commander/README.md)。
