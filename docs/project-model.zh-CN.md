# 以项目、镜像和镜像文件为中心

状态：2026-10-27，产品与概念模型讨论稿，尚未实施。
这是对[用户流程](user-journeys.zh-CN.md)的进一步细化。
英文主文档见 [project-model.md](project-model.md)。
交互方式进一步见[Commander 模式的传输工作台](transfer-workspace.zh-CN.md)。

## 用户主要理解三个对象

| 对象 | 用户怎样理解 | 可以做什么 |
| --- | --- | --- |
| 项目 | 集中管理某一组镜像的地方 | 查看镜像，把镜像复制进来或复制出去，清理选中的内容 |
| 镜像 | 一个软件包，有名称、版本和具体内容 | 在本机和项目之间复制，改目标名称，导出，删除指定副本 |
| 镜像文件 | 导出来、可以携带的软件包文件 | 检查内容，导入本机或项目，删除这个文件 |

本机已有的镜像独立存在，不要求先分配到一个远端项目。
一个文件可能包含多个镜像或多个平台，不能强制规定“一个文件只对应一个镜像”。
Tag 是镜像的版本名称，项目才是上传时主要选择的目标。

## 仓库和登录身份拆开，作为项目的支撑

这里把“镜像仓库”明确指向远端服务，例如某个 Harbor 服务地址；
项目下具体的镜像名称则单独表示，避免两种“仓库”混淆。

- **仓库服务**：记住地址、名称、服务类型和证书等连接信息。
- **访问凭证**：记住“使用哪个账号”，秘密保存在安全存储或本次会话中。
- **项目访问方式**：把项目和账号关联起来，记录该身份已确认可以做哪些操作。

仓库和凭证是两个独立概念。新增第二个账号时，应复用已有的仓库地址，
而不是把同一仓库和项目又复制一份。

关系是：

- 一个仓库服务可以提供多个项目，也可以配置多个凭证。
- 一个项目可以通过多个凭证访问。
- 一个凭证可以访问多个项目，在每个项目里的权限可能不同。
- 查看、读取、上传和删除分别判断；不知道某个权限时显示“尚未确认”。
- 权限最终取决于服务端对该账号和具体操作的判断，工具不能通过本地配置赋予权限。

## 例如：一个 Edge 项目

以下账号和权限只用于说明模型，不代表真实配置：

```text
Edge 项目 · 公司仓库
├─ 镜像
│  ├─ service-api
│  │  ├─ 1.4
│  │  └─ 1.3
│  └─ worker
│     └─ 2.0
└─ 访问方式
   ├─ 只读账号：已确认可以查看和读取
   ├─ 发布账号：已确认可以上传
   └─ 维护账号：已确认可以执行特定范围的删除
```

用户看到的是一个 Edge 项目。切换访问账号，项目身份保持不变；
不能因为添加了三个凭证，就出现三个看起来相同的 Edge 项目。
也不能把三个账号的权限合并成一个“什么都能做”的账号。

项目列表可以合并多个账号发现的同一个远端项目，并保留发现来源。
进入项目查看镜像时，应明确使用哪一个账号；切换账号后重新读取，
不会悄悄把不同账号看到的内容混成一份列表。

## 上传流程变成“选项目”，账号按需要处理

1. 在“本机镜像”找到软件包，选择“复制到项目……”。
2. 直接选择“Edge 项目 · 公司仓库”。同名项目要展示所属仓库，避免选错。
3. 确认项目内的镜像名称和版本，系统组合出完整目标地址供查看。
4. 使用用户为这个项目指定的上传账号。只有一个适用账号时可作为默认，
   同时提供查看和更换入口。
5. 多个账号都能上传且尚未指定默认时，让用户选择一次；不擅自选择权限最大的账号。
6. 需要登录则登录，缺少权限则明确选择其他账号或项目，保留原有输入。
7. 检查冲突，确认复制，核验后打开这个项目里的目标镜像。

如果权限无法事先确认，要说明状态并处理实际操作的结果。
不能为了测试权限，偷偷上传或删除一个测试镜像。

项目之间复制时，来源可以用只读账号，目标使用发布账号。
即使两个项目位于同一个仓库，也可能需要分别使用不同凭证；
底层必须保持来源与目标的身份隔离，不能悄悄让一个账号替代另一个。
当前程序尚有限制，这属于后续改造范围。

遇到拒绝访问时，不能自动换成更高权限账号继续执行。
更换身份由用户明确选择；已排队任务不跟随其他页面的账号切换而改变身份。
同一身份的登录续期可以继续任务，更换身份或目标需要重新检查相关操作。

## “添加项目”可以带着完成连接和登录

主入口可以是“添加项目”，意思是把**已有远端项目**加进本工具：

1. 选择已有仓库，或填写一个新的仓库地址。
2. 选择已有账号，或添加登录凭证；公开访问可以使用匿名身份。
3. 列出这个身份能发现的项目，选择要加入项目列表的项目。
4. 若服务不支持项目列举，允许填写确切的项目或命名空间，并说明这个映射。
5. 返回刚才的浏览或复制流程，保留已选镜像和目标输入。

“加入项目列表”和“在远端新建项目”必须区分。后者需要服务支持和对应权限，
不能成为添加快捷入口时的隐式操作。

移除账号只移除这个访问凭证；移除项目快捷入口只移除本地记录。
两者都不会自动删除远端镜像。凭证过期后，项目仍保留，显示需要重新登录。

## 镜像文件与项目的关系

导出时，选择镜像和平台范围，保存成一个经过核验的文件。
已知来源时，可以保留“来自哪个项目、哪个镜像版本”等说明，但它只是来源记录：

- 文件不永久绑定某个项目，可以分别导入多个目标项目。
- 外部拿来的文件可以没有已知来源项目，检查后照样选择导入目标。
- 来源记录和文件名不等于内容已经核验；文件被替换或修改后需要重新检查。
- 文件不包含账号密码或令牌，导入时使用当前目标项目的访问方式。
- 删除项目中的副本，不会顺带删除导出文件；删除文件也不会删除项目镜像。

本机镜像、项目里的镜像副本、导出文件可以有已知的内容对应关系，
但它们是不同位置的副本，有各自的生命周期。

## 清理也以项目和实际副本为范围

进入项目，选择镜像版本，说明实际会删除哪些名称和内容，再检查该身份的删除权限。
上传权限不代表删除权限。需要另一个账号时，明确提示切换并重新确认。

本机清理和文件删除分别处理，不提供跨位置的隐式连带删除。
同一内容多个名字时，仍需解释实际影响范围；删除后的物理空间回收不能直接保证。

## 同名项目和跨仓库业务

“仓库 A 的 Edge”和“仓库 B 的 Edge”是两个不同的远端目标，不能只按项目名合并。
一个真实远端项目的身份需要包含所属仓库和项目标识。

如果希望把测试、生产等多个远端目标放在同一个业务项目下，可以再增加业务分组。
分组由用户明确建立，组内每个远端目标仍然有独立地址、内容和访问方式。
初版先把远端项目身份与访问身份分清，不预设所有同名项目就是同一业务。

Harbor 有原生项目；其他服务可能使用命名空间或不同的组织方式。
工具可以统一呈现项目视图，但不能仅凭镜像路径的第一段就假定存在真实项目及相同权限规则。
技术依据见英文主文档列出的 Harbor 与 OCI 官方资料。

## 对现有设计的调整

项目、镜像、镜像文件是主操作对象；仓库和凭证进入连接与访问设置，
并在需要时从项目流程中进入。普通上传先选择项目，随后解决身份与权限。

现有程序把服务地址和账号保存在同一 Profile 中，需要后续拆分模型、存储和任务引用，
保留历史记录及安全凭证引用。本轮只确认这些定义和流程，尚未修改程序。
